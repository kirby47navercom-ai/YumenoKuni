# 21 — 모노패드 정보 열람과 스킬 장착 입력

## 범위와 근거 구분

제공된 PC 설치본의 복원 코드와 `Techou.dat`·`Skill.dat`·`Kousoku.dat`를 연결한 정적 분석이다. 원본/복원본의 동일성 범위는08과 같다. 이번 조사에서 원작 패드 화면을 직접 열어 모든 항목을 조작한 것은 아니다. 지도 이동은15, 선물 지급·친밀도 보상은02, 장착 뒤의 재판 효과는04를 따른다. 여기서는 목록을 여는 입력, 공개·소유·사용 조건, 취소·복귀와 실제 장착 상태 변경에 한정한다.

## 6개 아이콘과 10개 하위 모듈

`420b40`의 기본 선택은 지도·언령·선물·통신부·교칙·시스템의 6개다. `410380`은 이를 포함해 10개 하위 모듈을 매 tick 관리한다. 옵션·저장 확인·통신부에서 열리는 스킬 창이 기본 아이콘 수와 별도 모듈이므로, 원작 스킬 메뉴가 없다는 해석은 잘못이다.

선택 인덱스는 좌우 이동으로 0~5를 순환한다. 확정은 `53b250`의 `Techou` 공개 bit와 항목별 진행·현재 모드 조건을 함께 통과해야 한다. 공개 bit는 영속 상태 `+0x2420+(saveNo>>5)×4`에 있고, 진입 `537710`은 별도의 `+0x2430` 새 표시 bit를 끈다. 새 표시를 지우는 것과 항목을 해금하는 것은 다르다. 지도·언령·통신부·교칙에 서로 다른 조건이 있으므로 아이콘이 보이거나 커서가 도달했다는 사실만으로 모두 사용 가능하다고 하지 않는다.

하위 창은 준비→진입 연출→선택→퇴장 연출→반환을 나눈다. 공통 manager는 반환 `-1`이면 top을 다시 활성화한다. 통신부의 반환 `1`은 top 복귀가 아니라 스킬 창으로 연결하고, 스킬 창이 닫히면 통신부를 다시 연다. top 취소는 하위 창과 공통 도움말 자원의 종료 준비를 기다린 뒤 원래 플레이로 돌아가며 종료 후 30tick의 상태도 별도로 둔다. 로딩 중 입력을 즉시 다음 화면 선택으로 처리하는 구조가 아니다.

패드 진입 `47c000(world,1)`과 종료 `47c000(world,0)`는 world `+0xab50`을 바꾼다. 이 필드가 일부 월드 입력·표시 소비를 막는 근거는 있으나, 이것만으로 모든 타이머·애니메이션·음성이 멈춘다고 결론 내리지 않는다. 특히 `35a460`의 해당 gate와 말미 countdown 호출은 별도 조건이다. 시간 제한의 실제 pause 정책은03의 명시적 조건과 구분한다.

## 통신부: 공개된 인물과 공개된 페이지

`40c820`은 통신부의 준비·입장·선택·퇴장 상태기이고 `40ea90`이 실제 선택 입력이다. `40cda0`은 16개 인물 기록을 만들며 각각 40byte 단위로 기술 라벨, 공개·현재 상태, 진행값과 페이지 수를 구성한다. 본편 모드와 별도 일상 모드에서 다른 초기화 분기를 사용하고 현재 주인공 구성에도 예외가 있으므로 팬게임의 고정 인물 순서를 그대로 대입하지 않는다.

인물 변경은 0~15를 순환하되 기록의 선택 허용값이 0인 인물은 건너뛴다. 인물을 바꾸면 페이지 위치를 0으로 되돌리고 인물·상태 표시를 갱신한다. 페이지 수는 진행값이 6 미만이면 그 값, 그 이상이면 7로 잡는 경로가 있으며 주인공 기록에는 별도 기본 페이지가 있다. 따라서 모든 인물에게 모든 통신부 본문이 처음부터 열려 있는 구조가 아니다. 사망 상태 그림 자원이 존재한다는 사실과 해당 인물이 언제 그 표시로 바뀌는 조건은 구분한다.

상하 이동은 해당 인물의 페이지 수가 2 이상일 때만 의미가 있고 끝에서 순환한다. 별도 기능 입력 `3c8100`은 허용 필드 `+0x3cc`, 선택 인물의 지정 표시값, 페이지 위치 1을 모두 검사해야 스킬 창 결과 `1`을 반환한다. `40cda0`은 현재 장면 `+0x16a4==2`에서 이 허용 필드를 0으로 만든다. 즉 재판 장면에서 통신부를 열람하는 것과 스킬 편집으로 들어가는 권한은 별도다. 이 특정 진입 제한을 모든 화면·모든 모드의 스킬 변경 금지로 확장하지 않는다.

취소는 결과 `-1`을 남기고 퇴장 연출 뒤 top으로 복귀한다. 스킬 창에 들어갔다 돌아올 때는 원래 통신부 흐름을 다시 연결하며, 친밀도나 새 스킬을 얻는 보상 처리를 이 입력 함수가 대신 수행하지 않는다.

## 선물: 열람과 선택, 새 표시와 소모

`41c3f0`은 9열×3행, 한 화면 최대 27개의 아이콘을 관리한다. 실제 인덱스는 `(스크롤행+선택행)×9+선택열`이고, `41c750`은 Item 표 전체를 순회하며 24byte 레코드에 보유 수·새 표시·공개 여부를 채운다. 소지품 맵의 양수 항목만 모은 목록과 다르며, 보유 수가 전체 아이템 종류 수나 화면 칸 수를 정하지 않는다. 방향 이동과 행 스크롤은 유효 목록 끝에서 보정된다.

공통 manager의 진입 모드가 0 또는 2이면 `41c730(...,0)`으로 열람 모드를, 그 외 분기는 1로 선택 모드를 요청한다. 원시 caller의 RDX 설정까지 확인했으며, pseudo에 인자가 누락된 두 동일 호출을 같은 동작으로 합치지 않았다. `+0x114==1`이 아니면 결정 입력을 받아도 선물을 반환하는 확인창으로 가지 않는다.

선택 모드에서는 레코드의 `+0xc` 보유 수가 양수이고 `+0x10` 허용 상태가 있어야 확인창으로 간다. `Item`의 선물 가능값도 검사하며 확인창에서 다시 검증한다. 취소·거절은 선택 없이 열람으로 돌아가고, 확인 성공 시에만 선택 Item을 반환한다. 실제 지급 뒤의 수량 차감과 반응은02의 외부 소비 단계다. 열람에서 커서를 바꾸거나 창을 닫을 때 `41dfd0→537420`으로 새 표시를 지우는 동작을 수량 감소라고 해석하지 않는다.

## 교칙: 공개 목록의 페이지 이동

`41e410`은 교칙 상태기이고, `41f590`은 표 16행을 그대로 전체 공개하지 않는다. 먼저 표지 성격의 항목을 인덱스 `-1`로 하나 만들고, 공개 검사 `539f10`을 통과한 행을 추가한다. 기술 라벨 `kousokuLast`는 별도 포함 조건이므로 일반 공개 bit만으로 전 페이지를 설명하지 않는다. 이 포함 규칙이 교칙 내용을 사용자에게 전부 공개했다는 뜻은 아니다.

`41f390`은 위·아래 입력으로 페이지를 바꾸며 첫 페이지보다 앞이나 마지막 페이지보다 뒤로 순환하지 않는다. 변경 때 이전/다음 위치와 전환 방향을 기록하고 연출 완료를 기다린 뒤 선택 상태로 돌아간다. 취소는 현재 페이지 자원을 퇴장시킨 뒤 `-1`을 반환하여 top으로 복귀한다. 교칙 창의 결정 입력으로 임의 교칙을 획득하거나 진행 상태를 바꾸는 경로는 이 소비 함수에 없다.

## 스킬: 구매·획득·장착·해제를 분리

`4003c0`이 스킬 창 상태기, `4023f0`이 7행 목록의 실제 입력이며, `403250/402d80`은 별도 장착 목록의 표시·입력이다. 전체 목록의 선택은 보이는 행과 스크롤 시작의 합이고 한 번에 7행을 넘기는 경로도 있다. 전체 목록 48종과 한 화면 7행은 다른 수치다.

`530560 → 4a3970`은 열 이름/번호 쌍으로 실제 행 오프셋을 바인딩한다. native field 3=구매FP(원시 열3), 5=필요슬롯(원시 열4), 7=장비그룹(원시 열6)이다. native field 4에 교환CP를 먼저 두므로 이후 번호를 원시 열 순서로 읽으면 의미가 어긋난다. 11개 이름의 실제 매핑을 외부 원장에 보존했다.

획득 조회 `53a7d0`는 영속 상태 `+0xafac`, 장착 조회 `53a750`와 쓰기 `53e0d0`는 `+0xafa4`의 `Skill` saveNo bit를 사용한다. 획득하지 않은 항목과 장착하지 않은 항목을 같은 상태로 표시하면 안 된다.

- **구매**: 미획득이고 FP 가격이 0이 아닌 항목은 `402200`에서 현재 FP와 가격을 비교한다. 부족하면 부족량 안내, 충분하면 확인창으로 간다. 확인 결과가 1일 때만 `53eb80`으로 FP를 차감하고 `53e230`으로 획득 bit를 켠다. 취소는 차감하지 않는다. 이 구매 성공 분기에 장착 bit를 켜는 호출은 없으므로 구매와 자동 장착을 동일시하지 않는다.
- **장착**: 이미 획득한 미장착 항목은 `402290`의 검사를 통과해야 한다. 현재 장착 슬롯 합에 후보의 필요 슬롯을 더한 값이 `min(저장된 용량 +0x241c,99)` 이하여야 하며, 장착된 같은 그룹이 있으면 거부한다. 그룹 `-1`은 이 중복 그룹 검사를 적용하지 않는다. 실패는 미획득/용량 부족/같은 그룹 충돌을 구분한다. 통과한 입력만 `53e0d0(label,1)`을 호출한다.
- **해제**: 전체 목록에서 이미 장착된 항목을 결정하거나 별도 장착 목록에서 결정하면 `53e0d0(label,0)`으로 해제한다. FP를 돌려주거나 획득 bit를 없애는 동작이 아니다. 별도 목록은 최대 7행을 보여주며 제거 뒤 커서·스크롤을 유효 범위로 보정하고, 마지막 항목을 제거하면 원래 목록으로 연결한다.

`402ba0`은 표시 상태를 미획득·구매 가능/불가·장착 가능/불가·장착 중으로 구분한다. 용량 합은 `403170`이 장착 bit가 켜진 항목의 필요 슬롯만 더한다. 창 종료 시 UI 자원은 해제되고 `53e2f0`은 영속 상태의 `+0x2416`을 갱신한다. 이는 디스크 저장 성공을 뜻하지 않는다. 모든 스킬 효과와 다른 전투 상태의 우선순위는04 범위이며 여기서 반복하지 않는다.

## 패드 진입과 시스템 저장의 권한 층

일상과 수사는 wkMode1의 공통 탐색 경로를 쓰고, 재판 wkMode2는 대본 대기와 판정 하위 상태를 구분한다.478c90은 패드 flag 외에도 영화·객체 존재·입력/자원 준비·world+0xab40 등을 함께 검사한다. 부제목이 수사나 장끝으로 바뀌는 것만으로 권한이 바뀌지 않는다. 모드 표·장끝 예외·실제 쓰기 결과는 [09](09_시스템.md)의 후속 절을 따른다.

시스템 진입은 top420b40의 `system` SaveNo7 공개 bit를 통과해야 한다. 들어간 뒤41fa10의 `save` 커서1 실행에는 `save` SaveNo70 공개 bit나 wkMode·패드 호출 mode를 다시 검사하는 분기가 없다. mode2는 초기 커서·열람/선택 종류에 영향을 주지만 저장을 일괄 금지하지 않는다. 이는 시스템 UI에 도달했다는 전제에서의 실행 경로다.

## 팬게임 Pad.hpp와의 차이

분석 시점의 `Game/Source/Pad.hpp`는 6개 아이콘을 갖고, 일반 목록은 최대 12행을 표시하며 통신부 인물 15명을 고정 배열로 사용한다. 원작 수치 16명을 팬게임 인물 수로 강제할 필요는 없지만, 진행 조건에 따라 선택 가능 인물·열람 가능 페이지를 따로 구성하는 규칙은 현재 고정 목록과 다르다.

현재 팬게임 선물은 소지 맵을 읽어 목록을 만들고 상세 정보는 등급 중심이다. 원작의 열람/선택 모드·선물 허용 조건·새 표시 제거·지급 후 소모는 서로 다른 상태로 다뤄야 한다. 교칙도 전체 JSON을 바로 나열하므로 공개 조건·이전/다음 페이지와 전환 대기를 별도로 표현해야 한다.

팬게임 통신부에는 획득/장착 여부를 글로 표시하지만 `updatePad()`에는 스킬 목록 진입·구매·용량 거부·그룹 충돌·장착/해제 입력이 없다. 관계 단계에 따라 효과가 보인다는 사실이 원작 장착 편집을 재현한 것은 아니다. top의 공개 bit·모드별 거부와 하위 창 복귀도 단순 6개 페이지 토글과 구분할 필요가 있다. 이 문서는 차이를 기록한 것이며 이번 조사에서 팬게임 코드를 변경하지 않았다.

## 본편 패드와 공통HUD의 갱신 경계

본편의 패드 열람은 지도 이동 확정과 다르다. main478c90에서 pad latch가켜지고 목적map−1인 활성 경로는 공통HUD 갱신으로 이어질 수 있다. 목적map을 고르면 탐색 정리를 요청하고 pad 종료를 기다리는 별도 경로다. pad+0x50의 nonzero 판정은 열려 보이는 메뉴뿐 아니라 종료 cooldown도 포함한다. display flag ab50만으로 모든 시간이 멈춘다고 구현하지 않는다.

수사 타이머의 갱신 호출까지 이어지는 조건과 실행 한계는 [03_수사.md](03_수사.md)의 패드 후속 절에 보존했다. 이는 본편 세계의 분배 계약이며 재판의 다른 pad caller15f700이나 시스템 pause 전체에 그대로 적용하지 않는다. 이번 분석으로 실제 전 메뉴의 시간 정지를 검증한 것은 아니다.

`420b40`은 자원/표시 준비 뒤 `fl_in`과 패드 열림음 `V3_SE_015`를 요청한다. 완료 후 `fl_wait`에서6개 아이콘을 선택한다. 실제 callback420880의 커서음은SE005,4208e0의 확정음은SE001,4208b0의 top 닫기음은SE016이다. 비공개/모드 불허 항목은SE000과 안내를 유지한다. 아이콘 이름·NEW·설명 `setumei_text`·선택 효과와 하위 창 제목 전환은 별도 부품이다. 진입한 항목의 공개 NEW bit를 지우는 것은 소유 아이템 소모나 공개 해금과 다르다.

### 언령·통신부·선물·교칙의 표시와 선택

언령 `412360`은 두 자원 `techou_kotodama`와 `_list`를 기다려 `fl_in`을 요청하고, 두 클립이 끝나면 현재 행의 `fl_wait_000..010`으로 강조한다. 새 근거 `413310`은11행 목록·스크롤과11행 단위 페이지 이동을 구현한다. 커서/페이지가 바뀌면 하위 그림 선택을0으로 돌리고 기존 내용 표현을 리셋해 `413120`으로 새 설명을 요청한다. 복수 그림이2개 이상인 항목은 별도 좌우 입력으로 그림 index를 순환하고SE005를 낸다. 일반 목록 이동도SE005,취소는SE004와 두 자원 `fl_out`·완료 대기·해제를 거쳐 top 복귀다. 열람 커서 이동을 증거 획득/사건 진행으로 구현하지 않는다.

커서/페이지 이동은SE005,취소는SE004다. ### 시스템·탐색·저장·재개에 연결하는 경계

시스템 `41fa10`의 표시 자원은 `fl_option/save/load/backlog/mainmenu/kisekae`와 각 `_ok/_ok_out`, `system_notice`를 구분한다. 정적 callback41f840/41f870/41f8a0/41f900은 각각SE005/001/004/000을 낸다. 선택 커서·실행 가능 상태·확정 전환을 구분하고, 옵션의 값유지 취소와 저장의 확인/완료/성공은09의 정상 표현 계약을 따른다.

패드에서 구매·장착·선물 NEW 제거는 공통 영속 상태의 RAM bank를 갱신한다. 스킬은 획득+afac와 장착+afa4를 분리하며 재판 효과 소비가 장착 bit를 읽는04의 계약과 연결된다. `477a00→53ccb0` 저장 스냅샷과 실제 writer 완료/성공은 별도다. Continue는 공통 payload에서 월드·모드·대본 위치를 복원한 뒤 입력 준비를 검사하며, 패드를 닫았다는 사실만으로 매번 자동 파일 저장이 실행됐다고 쓰지 않는다.

일반 열람 취소는 같은 탐색/대본으로 복귀한다. 지도 목적지를 확정하면15의 remap→정리→동일맵 위치 적용 또는 wrapper→MAP 로드를 따른다. 본편 `ab50`·패드 latch·종료 cooldown과 타이머 dispatch의 gate는 서로 다르다. 수사의 제한시간·HUD는03의 실제 호출 조건을 그대로 사용하고, 패드만 열리면 음성/연출/모든 시간이 멈춘다는 공통 pause를 새로 만들지 않는다.
