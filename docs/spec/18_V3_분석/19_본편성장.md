# 본편의 행동 보상·경험치·레벨

본편의 성장은 재판 정산과 별도 경로예요. 여기서는 설치본의 행동별 경험치 표→호출 조건→누적 상태→레벨 표 조회를 연결했어요. 실제 레벨 상승 화면·모든 보상 중복 방지·능력치의 최종 소비까지 완료했다는 뜻은 아니에요. 육성·던전 RPG의 캐릭터 레벨은 10 문서의 별도 시스템이에요.

## 행동과 보상

설치 파일의 표 이름은 정확히 `Experiance.dat`예요. 11행·행당4바이트이며 ID는 +0의 label, 경험치는 +2의 u16이에요. `3960c0`이 이 표를 로드하고, `396220`이 이름으로 행을 찾은 뒤 enum1 값을 읽어 `536f10`에 전달해요. enum과 실제 열의 대응은 열 이름 등록 경로와 대조했어요.

수치의 분모는 **함수 호출1회**예요. 고유 물체 수·실제 플레이 중 지급 횟수·한 장의 총량으로 읽지 않아요. 유효한 조사 대상 확인과 별개로, 반복 지급을 막는 모든 호출자 조건은 아직 닫히지 않았어요.

`409010`에서 보행 위상을 갱신하고 경계를 넘으면 발소리 처리와 Walk 보상을 함께 호출해요. 정지할 때도 위상을 끝까지 정리하는 분기가 있어요. 따라서 현재 근거를 이동 거리 몇 m당 지급으로 바꾸지 않아요. 시점 흔들림 옵션은 보상 호출 뒤에 조회하므로, 시점 흔들림을 껐다는 이유로 이 함수의 경험치 경로까지 사라지지는 않아요.

`409290`의 UseConcentration은 초기 상태에서 지급해요. 집중 키를 누른 매 tick마다6을 준다고 일반화하지 않아요. `409540`·`40a6a0`은 대상의 종류를 확인한 뒤 TalkCharacter/CheckObject를 고르므로 빈 곳 클릭과 구분해요. `40c470`도 물체 반응의 카운터 종료를 보상과 연결하므로 모든 타격 입력을 곧바로 보상으로 세지 않아요.

`46af30`의 언령 등록 경로와 획득 UI 경로도 구분해요. 등록 함수 호출 수를 그대로 GetKotodama 지급 횟수로 계산하지 않아요. 슬롯 main의 디컴파일에는 두 번째 인자가 빠졌지만 raw `321bd3`의 LEA RDX를 따라 `74acc8`의 문자열 `SlotMachine`을 직접 확인했어요. 따라서 이 레버 경로도 표의 경험치1과 연결할 수 있어요.

실효 US007 대본2,716개에서 literal EXP는239개예요. 모두 non-test 경로의 명령이고 라벨별로 GetKakera124·GetKakureMonokuma109·Script6개예요. 이것은 텍스트상 호출 분모예요. 서로 배타적인 분기·재사용·실제 도달 여부를 포함한 실행 횟수는 아니에요. 전체 명령·파일 해시는 저장소 밖 `native/xp_script_calls007.json`에 있어요.

## 물체 타격의 메달·반응 완료·경험치는 따로 판정한다

`40c470`은 UI 준비를 기다린 뒤 선택 물체의 유효성과 `3bdf30`의 허용 조건을 검사해요. 시작 효과음은 `V3_SE_075`, 유효 타격 피드백은 `V3_SE_076`예요. 보상 변경이 허용된 경우 `536e90`은 영속 타격 카운터 `+2648`을 올리고100,000으로 제한하며1,000 임계값에서 업적 요청을 해요. 이 카운터 증가 자체를 메달 지급으로 읽지 않아요.

로컬 물체 `+94`가 양수이면 하나 줄이고 `40c640→35f120→353120/362f00→35d060`으로 메달 표시를 요청해요. 실제 지급 판정 `458360`은 현재 저장 맵 `+5e28`과 선택 물체 ID로 영속16바이트 레코드를 찾아요. 레코드의 남은 수량 `+1faf`가0이 아닐 때만 하나 줄이고 지급량 `+1fae`를 `536e60`으로 넘겨 잔액 `+2636`에 더해요. 잔액 상한은999예요. **잔액 갱신은 표시 애니메이션 완료를 기다리지 않아요.** 반환량0이면 표시 요청도 끝내고, 양수이면 양이10 미만/이상인지에 따라 `fl_in_1/2`를 고른 뒤 표시 상태6으로 들어가요. 로컬 지급 횟수와 영속 재고는 별도 검사예요.

물체 `+88`은 반응 완료를 결정하는 별도 카운터예요. 감소 후에도 양수이면 반응 variant0만 시작하고 경험치 없이 행동을 끝내요.0이면 `ObjectReaction` 경험치2와 알림을 요청하고 `3be9e0`으로 등록된 반응 종류 `+190`을 시작해요. 따라서 메달을 받았지만 반응이 아직 끝나지 않은 타격, 메달 없이 반응 완료 경험치를 받는 타격을 구분해야 해요.

`409540/40a6a0`의 TalkCharacter/CheckObject 경험치는 상호작용 초기 단계에서 지급하고 대기 단계의 매 업데이트마다 다시 지급하지 않아요. 다만 이 함수들에는 대상별 영구1회 제한이 없어요. 일반 target 생산자 `40bb50`은 **반응 가능 `+84≠0`이고 남은 반응 횟수 `+88<1`이면** 선택 target `+240`을 기록하기 전에 돌아가요. 따라서 반응 완료 물체의 일반 재선택 차단은 여기서 성립해요. 하위 `3bdf30`은 `+84/+19c`와 연결 상태를 보지만 `+88` 자체를 검사하지 않고, `3be9e0`도 직접 비활성화가 아닌 반응 초기화예요. 상위 선택 차단을 하위 자격 함수의 효과로 잘못 옮기지 않아요. 이 정상 경로와 재로드·대본 강제 요청은 별도이며, 같은 대상의 모든 TalkCharacter/CheckObject 경험치에 영구1회 제한이 있다고 일반화하지 않아요. 영속 재고 생성·직렬화 경계도 별도예요. 선택 차단 근거는 `ev_8004a03ef19bcdf471e6afe2147193bee9980fb0c2e3f521565ad18475cf429d`예요.

직접 근거: 타격 `ev_e50288ab79428ff50867232b08fafad5b819ca4545cf8ffaddd0a2faf947c187`, 표시 진입 `ev_9f1ab7db9d2d1c599d565438642ad429ead5460ac03e8eccd288323da1763df2`, 영속 지급 판정 `ev_8cbf90f31df98d62e67f5be79fcda8ef75afb86a9bcd97ee72075e8a498d56cb`, 잔액 `ev_1ee0e333238de66c7cea9cfb050d2230f74bac7fcafec43e64384081597c8b6d`, 타격 횟수 `ev_c273b16a359a98d42e9ce9d2320031f02fa90c220c4b13cef88b1530703fe6ff`, 허용 조건 `ev_fddc04c0d77fcbd08aaffae1e40e139531ab03056ab2cb6d4ffd5f3c31351aee`, 완료 반응 `ev_b2e0fd70312df75af9ad18457c6cd135517d14250a69c7c3637eb162a8f549e3`예요. 외부 `object_reward_findings.json`과 재현 helper는15개 캐시 함수 및 명시적 가상 사례5개를 대조해요. 가상 지급량5는 계산 예시이며 원작 모든 물체의 지급량이나 실행 결과가 아니에요.

## 경험치와 레벨 상태

`536f10`은 본편 상태 +0x2410의 u32 경험치에 표의 값을 더하고168,500을 상한으로 둬요. `52e620`은 Level 표에서 누적 경험치 이하인 임계값 중 가장 큰 것을 선택하고, `52e7d0`이 그 행의 레벨을 읽어요. 새 레벨이 기존 +0x240c의 u16보다 큰 경우에만 레벨과 +0x241c를 갱신해요. +0x241c도99를 상한으로 두며, 후속 패드 분석에서 스킬 장착 최대 용량 소비로 연결됐어요. 98→99에만 추가 업적 호출 조건이 보여요.

원시 getter `53a930`은 같은 전역 `140d20080`을 읽어 +0x241c의u16을 반환해요. 스킬 선택 판정 `402290`은 이를99로 제한한 값과 `403170`의 현재 장착 필요 용량 합+선택 스킬의 필요 용량을 비교해요. 따라서 이 필드는 단순 표시용 레벨이나 장착 스킬 개수가 아니라 **스킬 비용 합을 허용하는 용량**으로 쓰여요. 그룹 중복·획득/구매·장착 상태는 별도 조건이며 패드 정보 분석을 따라요. 근거 `ev_a8d99a756b1a8f97ca97ccdea492a4675429375ab638874196e69f24e8b9fdd0`, `ev_ebf7c29c6ac5774f2b2400024f0e33fec9a9f70f77de7142231f29d7b8f5a2d8`, 외부 `native/pad_info_disassembly.json`의53a930/402290 원시 경로예요. 실제 장착 화면·모든 효과 소비까지 관찰한 것으로 세지는 않아요.

`53e160`은 경험치를 직접 설정하는 별도 함수예요. 동일한168,500 상한과 증가 방향 레벨 갱신이 있지만 실제 호출자는 닫히지 않았어요. 디컴파일에 함수가 있다는 이유로 레벨 하락·리셋의 사용자 기능을 추정하지 않아요.

## 실제 체력·집중 최대치와 현재치의 소비

동일한 영속 객체 `140d20080`에서 기본 체력은 u16 `+0x2414`, 현재 체력은 `+0x2416`, 기본 집중은 `+0x2418`, 현재 집중은 `+0x241a`예요. 초기화 `53b790`은 두 기본값을 각각10,000으로 놓고, 최대치 getter를 호출한 결과로 현재값을 채워요. 표시 막대만 조회하는 자료가 아니라 다음 실제 감소·회복 소비로 연결돼요.

`53a9c0`은 기본 체력에 장착된 `POWERFUL_VOICE_LV2`의 증가값을 우선 더하고, 없으면 LV1을 검사해요. `53a5c0`은 집중에 대해 `CONCENTRATION_LV2→LV1` 순서로 같은 일을 해요. 확인한 Skill 증가값은 LV1=4,000·LV2=10,000이므로 기본값이10,000이면 최대치는 무장착10,000/LV1 14,000/LV2 20,000이에요. 두 단계가 동시에 켜져도 합산하지 않고 LV2를 우선해요. 조회하는 bit는 획득이 아닌 장착 `+0xafa4`예요.

별도 `53aaa0`은 체력 LV1 증가값만 절반으로 쓰는 변형이지만 직접 호출은 찾지 못했어요. 이를 특정 재판 모드의 규칙으로 임의 배정하지 않아요. 기본값 가산 leaf `536f00/537030`도 존재하지만 직접 호출은0회예요. 현재 확인한 경험치 갱신 `536f10`은 XP·레벨·장착 용량을 바꾸며 기본 체력·집중 필드는 쓰지 않아요.

| 완전 회복 | `53c9b0` 집중·`53c9d0` 체력은 대응 최대치로 현재값을 채워요 |

대본 피해 `474af0`의 `wHeartDamage -=`는 난이도 코드0/1/그 외에 각각25%/50%/100%를 적용한 뒤, 장착 VIABILITY의80%를 다시 적용하고 현재 체력에서 빼0으로 제한해요. `+=`는 장착 CHARISMA의200%를 적용한 회복량을 더하고 현재 최대치로 제한해요. `wAHeartDamage`는 별도 난이도 getter를 사용해요. 따라서 대본 인자2,000을 모든 모드의 실피해2,000으로 읽지 않아요. 논스톱 오답 자체는 대본 반응으로 이어지며, 이 입력마다 native에서 고정 피해를 직접 빼는 구조가 아니에요.

### 집중의 비용·회복은 모드마다 같지 않아요

## 행동·코인·선물·스킬과 일반 저장의 정상 연결
