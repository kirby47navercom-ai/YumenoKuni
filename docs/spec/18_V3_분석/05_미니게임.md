## 공통 헤더와 레코드

| 파일 오프셋 | 저장 형식 | 확인된 범위 |
|---:|---|---|
| 0 | little-endian u16 | 시간 기초값. 네이티브에서 60을 곱함 |
| 2 | u8 | 레코드 개수 |
| 3 | u8 | 별도 플래그. 개수의 상위 바이트로 합치면 안 됨 |
| 4 | u16 | 원시 설정값; 하위 바이트와 상위 바이트도 구분하여 사용 |
| 6, 8, 10 | 각각 u16 | 설정 ID. 정확한 소비 의미는 별도 추적 필요 |
| 12 | 행 시작 | 아래의 크기로 반복 |

기본 파일은 `12 + 개수×404 + 768`바이트다. 뒤의 768바이트는 **64바이트 고정 ASCII 슬롯 12개**이며 컷인·음성 참조가 들어 있다. 패딩이 아니다. 공백 슬롯과 실제 문자열을 구분해 모두 보존한다.

`nonstop_03_206.dat` 한 파일은 실제 행 간격 388바이트다. 순차 레코드 번호와 전체 크기를 대조하여 구조를 따로 읽었다. **현재 확인한 네이티브 공통 로더는 항상 404를 더하므로 이 예외 파일이 실제로 실행되는지는 확인하지 않았다.** 이 파일을 일반 404 재생 경로에 투입하면 안 된다.

이후 실효 US007의 본편 Data 직접 참조57개를 전수 대조했다. 모두404 간격 DAT이며 총1,926행이고, 위388 예외10행은 이57개 참조에 없다. 설치본 전체58파일·1,936행과 본편 직접 참조57파일·1,926행을 구분한다. 전체 실제 도달성까지 증명한 것은 아니다.

일반 행의 시작 u16은 대부분 순번이지만 `nonstop_04_202.dat`의 9·10·11번째 행에는 10·11·9가 저장되어 있다. 파서는 임의로 순서를 고치지 않는다.

## 논스톱: 실제 시간 변환과 벡터 인자

네이티브 `0x140484ed0`은 행 간격 `0x194=404`를 사용한다. 정확한 전체 본문은 `0x140484ed0..0x140485ec3`다. 다음은 추정한 필드 명칭이 아니라 실제 읽기·쓰기 변환이다.

| 행 내부 바이트 오프셋 | 원본 → 런타임 |
|---|---|
| 28, 32, 36, 40, 44, 48, 52, 56, 60 | float32×60 → 잘라낸 signed16 카운트 |
| 76 | float32×60 → signed16. 반론 모드에서는 해당 카운트를 0으로 두고 다른 필드에 float→short 저장 |
| 360 | float32×60 → int32 카운트 |
| 384 | float32×60 → signed16, 결과 0이면 1로 보정 |
| 120부터 36바이트 간격, 여섯 묶음 | 묶음마다 float32 9개를 읽어 런타임의 세 vec3 배열로 분산 |

마지막 여섯 묶음의 원본 범위는 행 +120..335다. 각 묶음의 vec3 세 개는 런타임 행 +104, +176, +248에서 시작하는 배열에 각각 들어가며 다음 묶음의 목적지는 +12씩 증가한다. 후속3e7000→4cd410→4ceb70→4cd950→실제 폰트 setter 대조로 **세 배열은 각 구간의 위치·회전·크기 변화율**임을 확인했다. 아래 공유 표현 절에서 초기값·분할 적분·최종 소비를 구분한다. 가속도나 세 개의 절대 위치라고 해석하지 않는다.

예를 들어 `nonstop_01_202.dat` 첫 행(파일 +12)의 +28에는 약 0.6, +32에는 약 5.7이 저장되어 있다. 실제 float32 곱셈을 재현하면 각각 36·342 카운트가 된다. Python double로 곱한 뒤 곧장 정수화하면 5.7이 341로 잘리는 오류가 생길 수 있어 파서 테스트로 막았다.

헤더 기초값은 `u16×60`으로 변환하며 `PONDER` 스킬이 있으면 스킬 테이블에서 읽은 퍼센트가 적용된다. 구체적인 스킬값과 화면 표시는 별도 근거 없이 만들지 않았다.

## 패닉: 세 자료 열

통상 논스톱의 대표 조준→글자별 삼각형 hit→탄환 두 슬롯→논파/동의/V포인트·소음→오답 대본의 피해→내부 복귀/전체 실패·Retry 연결은 [04_재판.md의 대표 논스톱 절](04_재판.md#논스톱-의논-대표-표본의-조준판정wrd-복귀)에 추가했다. 판정22개 네이티브 근거와 전체57 DAT 분모를 분리했으며, 패닉 세 열에 그 표본의 모든 조작·성공 조건을 자동 적용하지 않는다.

`0x1404835c0`의 패닉 분기는 `_1.dat`, `_2.dat`, `_3.dat`를 각기 읽고 `0x140484ed0(mode=1, lane=0/1/2)`에 넘긴다. 각 열은 자신의 404바이트 레코드와 개수를 가진다. 같은 문장 목록 하나를 사선 세 칸에 복제한 구조로 재구현해서는 이 차이가 사라진다.

실제 화면 각도·칸 좌표·큰 소리 판정·가림/강조 전환 시각은 아직 이 문서에서 확정하지 않았다.

## 반론 쇼다운: 별도의 그룹 꼬리

파일은 `12 + 개수×404 + 768 + 개수×12`바이트다. **416바이트 행으로 읽으면 안 된다.** 숫자상 전체 크기는 맞아도 두 번째 이후 행 경계가 틀어진다.

맨 뒤 `개수×12`바이트 영역은 공통 로더의 반론 분기에서 그룹을 읽는 데 쓰인다. 그룹 시작 바이트 0을 포함할 레코드 수로 사용하고, 다음 그룹으로 `그 수×12`바이트를 건너뛴다. 그룹 +8의 float 시간에는 60을 곱한다. 그룹의 세 번째 바이트는 선택 함수 반환값에 따라 -30 또는 -10 보정을 받는다. 해당 선택 함수를 난이도라고 단정할 추가 근거는 아직 없다.

한 파일에는 헤더 레코드 20개에 대해 그룹 크기 10+11이 저장되어 있다. 원래 루프도 누적값이 개수 이상이면 종료하므로, 파서는 이 차이를 경고로 남기고 자료를 버리지 않는다. 어떤 플레이 경로에서 쓰이는지는 추가 확인 대상이다.

## 의논 스크럼: 108바이트 행과 160바이트 보조표

`0x140484630`에서 확인한 파일 구조는 `12 + 개수×108 + 160 + 768`이다. 행 +8의 float에 60을 곱해 카운트로 바꾼다. 짝수 번호 행에는 `0x14053b210` 반환값 0일 때 ×1.5, 1일 때 ×1.2를 추가 적용한다. 선택 함수의 실제 설정명과 UI 연결은 아직 미확인이다.

행 뒤 160바이트도 빈 공간이 아니다.

| 영역 | 실제 읽기 |
|---|---|
| 앞 80바이트 | 16바이트 블록 5개. +4 float×60, 앞쪽 byte 카운터 두 개는 선택 함수 결과에 따라 -3/+3 또는 -1/+1 |
| 뒤 80바이트 | 8바이트 블록 10개. +0/+2/+4 u16, +6/+7 u8에는 각각 60을 곱함 |

768바이트 컷인·음성 슬롯은 이 보조표 뒤에서 시작한다. 현재 좌우 얼굴만 배치하는 `scrumFormation`과는 자료 단계부터 차이가 있다. 다만 이 표만 보고 실제 팀 분할 위치나 정답 판정식까지 완료로 표시하지 않는다.

## 스타일과 다른 재판 미니게임

`nonstop_type.dat`는 3,172바이트다. 시작 3,072바이트에 32바이트 ASCII 문자열 슬롯 96개가 있으며, 그 뒤 100바이트는 별도 원시값이다. 공통 네이티브 로더의 실제 복사 범위와도 일치한다. 스타일 참조 이름을 모두 보관했지만 꼬리의 색·플래그 의미는 확인 전까지 확정하지 않는다.

`mode_label.dat`와 `MOD` 핸들러로 섬광 애너그램·브레인 드라이브·발굴·이론 무장·클라이맥스·투표·결과·재시도 모드의 별도 진입 분기까지 확인했다. **각 모드의 조작·정답 판정·점수·카메라·모든 애니메이션은 아직 완전히 역분석하지 않았다.** 클라이맥스 DAT 6개는 논의 구조와 다르며, 별도 `map_data.py`가 native `0x14038f8f0`의 12-byte 헤더와 28/20/8-byte 세 그룹을 전부 해독한다. 합계210레코드의 경계·원시값 해독 뒤, 이 문서의 클라이맥스 절에서 빈칸 quad·후보 ID·해금·페이지 복기 소비까지 추가 대조했다. 실제 실행 화면 검증과 모든 UI 모션 완료는 별도다. 비정형 자료 전수 범위는 [10_보너스와_비정형_DAT.md](10_보너스와_비정형_DAT.md)에 있다.

재판 이외 `minigame/rsc`의 WRD 442개도 분석 범위에 포함한다. 설치본 `label.spc/command_label.dat`의 123행에서 명령 이름104개(0..103)와 별칭·상수19개를 분리했다. 이 별도 표로89,391명령의 이름과 바이트 경계를 해독했고 unknown opcode는0이다. 메인 표를 적용했을 때의49,702 unknown/27,353 인자 경고는 잘못된 방언 선택에서 나온 과거 결과다. 공통 명령의 인자 형식은 상속해 참조를 검증했지만 확장 명령30,453건의 인자 의미는 미확정이다. 원시값·오프셋·범위 내 parameter 후보를 보존하며 성공/육성/동작 효과를 이름만으로 확정하지 않는다.

1. `Game/Source/Debate.hpp`의 문장 데이터/애니메이션: 현재 추정 12종 모션을 원작 레코드에서 확인한 시간·벡터 체계와 대조하고, 소비식이 확인된 필드부터 재구현한다.

후보 설명은 실제 단서 포인터를 `climax_koma` 텍스트 슬롯에,선택 빈칸의 설명은 두 번째 단서 블록을 `climax_hukidasi`에 넘긴다. 미선택 빈칸은 해당 텍스트를 비운다. 잠긴 후보는 남은 필요 수를 공통 메시지 템플릿에 치환한다. 공통 text/image 소비에 전달하는 실제 값이며,자원 이름만 보고 추정한 설명문이 아니다.

3909a0은 미배치 빈칸이 선택됐고 해금 전환 중이 아니며 목록 확장 입력을 놓은 경우 확정을 받는다. 잠김/사용된 후보는 SE004로 거부하며 이 단계에서 체력을 깎지 않는다. 수락은 SE001,힌트 out/말풍선 out/커서 `fl_ok`/삽입 패널 `fl_in`을 요청한 뒤392230의 이동을 시작한다. 논리(252,886)에서 quad 중심으로20회 갱신 동안 위치·크기·회전을 보내며21번째 갱신에는 후보 ID 비교로 `fl_out_ok` 또는 `fl_out_ng`를 고른다. 해당 clip이 끝나야 실제 판정 단계로 넘어간다.

정답은 사용·배치 플래그와 완료 수를 갱신하고12번 컷인의 `fl_in`과 SE310을 요청한다. 이 컷인 완료 후에야 모든 빈칸 완료 여부를 검사하고,아직 남았다면 커서·힌트 상태를 복귀시킨다. 오답은13번 컷인과 SE311을 요청하고 완료를 기다린 뒤 SE316과 난도/VIABILITY를 적용한 체력 차감을 실행한다. 체력5/7/10분절과 시간 숫자는 실제 native 값으로 갱신한다. 시간은 정상 배치 대기 구간에서만 감소하며 삽입·정오답 피드백의 조기 반환 경로에서는 감소하지 않는다.

### 완성 뒤 만화·음성 대기와 성공/Retry

모든 빈칸을 채우면 곧바로 WRD 성공으로 복귀하지 않는다. SE448·완성 음성·21번 컷인을 요청하고 완료와 페이드 경계를 기다린다. type7 결과를 기록하고 조작용 핸들을 정리한 뒤 BGM085로 바꾸며20번 완성 만화와25/26번 페이지 전환을 준비한다. 페이지 `fl_in`과 SE007 뒤 준비/제어 상태를 확인해 패널별 `fl_in_N`을 요청한다.

각 패널은 clip 완료를 먼저 기다린다.20바이트 복기 행의 해당 값이1000 미만이면 지정 카운트만큼 기다려 다음 패널로 가며,1000 이상이면 값−1000만큼 기다린 뒤47afd0에 `page*10+panelIndex`를 전달한다.47afd0은 이 숫자를 현재 WRD의 실제 라벨 검색에 넘기고38d970은 script의6b4 완료 표시를 기다린다. 따라서 음성/대사 지연을 모든 패널에 같은 고정 시간으로 대체하지 않는다. 대표 장은 플레이 페이지10개와 복기 페이지11개가 다르며,첫 callback 값1030은30카운트 후 라벨2를 실행하는 구조다.

페이지 종료는 해당 clip과 WRD 전환 경계를 기다리고 `fl_out`을 요청한 뒤 다음 페이지 자원을 다시 준비한다. 이때6번째 갱신에 새 `fl_in`과 SE007을 요청하는 단계가 있으며 이전 out과 새 자원의 ready를 모두 기다린다. 마지막에는 공통 표현/음성 태스크 완료를 기다리고 SE327과22번 균열 SFL을 요청한다.22번 clip 완료 후 이를 해제하고23번 파괴 SFL·공통 표현 태스크를 요청하며,후속 태스크 완료와 페이드 종료·자원 정리를 거쳐야 루프가−1을 반환한다.23번 자체의 clip 완료를 별도 검사한다고 덧붙이지 않는다. 내부 카운트를 벽시계 초 실측으로 바꾸지 않는다.
