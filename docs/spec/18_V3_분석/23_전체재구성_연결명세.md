# V3 전체 재구성 연결 명세

목표는 자체 스토리·세계관을 유지하면서 V3의 조작·게임 규칙·진행·화면·소리의 연결을 구현하는 것이다. 기존 유메노쿠니 구현이 보존 기준이 되지 않는다. 이 문서는 개별 분석을 실제 구현의 공통 문맥과 완료 조건으로 묶는다. 세부 수치·파일·함수·Evidence는00~22와 numbers.json/evidence_index.json을 따른다. 현재 분석 결과를 실제 원작 실행 기록이라고 부르지 않는다.

## 공통 문맥

한 모드의 상태는 `진입 요청 → 자원 준비 → 진입 표현 → 조작 허용 → 판정/상태 변경 → 결과 표현 → 완료 확인 → 정리 → 호출자 재개`로 분리한다. 실제 모드가 생략하는 단계는 해당 소비 근거에 따른다. 모든 모드에 동일한 강제 대기나 가상의 완료 버튼을 삽입하지 않는다.

| 공통 계약 | 구현에 필요한 구분 |
|---|---|
| 논리 입력 | 물리 키/패드/마우스 설정→논리 행동→pressed/held/released/repeat를 구분한다. 한 프레임의 새 입력은 공유 스냅샷에서 소비하고 설정별 결정/취소 교환을 보존한다. |
| 호출 문맥 | 모드·맵/입구·대본/체크포인트·활성 호출 깊이·선택 대상/질문·난도·소지/성장 상태를 분리한다. UI의 리소스 준비 enum을 게임 모드 enum으로 해석하지 않는다. |
| 시간 | 정수 제한시간, float 재생 배율/구간 경과, SFL 프레임, 장식/입력 반복 카운터는 다른 시계다. 실제 caller가 허용한 갱신만 진행한다. 메뉴/표시 하나로 모든 시계를 일괄 정지시키지 않는다. |
| 상태 변경 | 비용 확정·지급·판정·플래그 쓰기는 실제 경계에서 한 번 수행하고, 매 표시 갱신과 분리한다. 수량과 영구 획득 이력, 소유와 장착, 선택량과 결제, 미결 비용과 실제 체력을 합치지 않는다. |
| 표현 | 자원 요청/준비·표시/변환·clip 시작/완료·Stop/반복·해제는 각각 다르다. 변화값만 엔진으로 전송하되 원작의 입력 잠금/완료 대기를 제거하지 않는다. |
| 저장 | RAM 상태 변경→snapshot→저장 요청→비동기 완료→성공 확인을 구분한다. 일반 GameData payload 범위[+20,+43e70)는 본편/성장/소지/카지노/별도 상태를 포함하며 별도 모드 snapshot도 실제 필드로 보존한다. |
| 결과 | 선택 ID/영역 번호, 정오답, HP/시간 실패, 단순 발언 한 바퀴 종료, 내부 재도전, 전체 Retry는 별도 결과다. bool 참을 공통 성공으로 가정하지 않는다. |

## 적용 순서와 검증할 경계

1. **공통 실행 문맥과 저장:** 입력 스냅샷·각 시계·대본 호출/복귀·모드 결과·비동기 자원/저장 경계를 먼저 만든다. 모든 게임플레이가 이 경계를 공유한다.
2. **탐색 공간과 일상/수사:** 원작의 공간·시점·충돌/대상/문·인물 배치·패드 좌표를 따른다. 기존 배경 밀기/목록 지도/그림 위 임의 hotspot을 보존 기준으로 쓰지 않는다. 초대→활동→시간, 조사→증거→종료 왕복을 먼저 관통시킨다.
3. **공통 표현과 게임별 판정:** 데이터 수치와 실제 소비를 사용해 UI·폰트·카메라·SE·애니메이션 준비/완료를 만든다. 미니게임은 모양만 모사하지 않고 해당 입력·판정·재도전·대본 결과까지 연결한다.
4. **보너스/성장/메뉴:** 본편과 별도 게임의 재화·캐릭터·snapshot을 혼합하지 않고 각자의 정상 고리를 공통 저장에 연결한다.
5. **실제 팬게임 검증:** 구현 뒤 대표 정상 입력/경계/내부 재도전/전체 실패·복귀·저장/Continue를 검증하고, 엔진 규정의 빌드와 전체 플로우/화면 검증을 수행한다. 이번 분석 작업에서는 Game 구현·에셋·빌드·스테이징·커밋을 수행하지 않는다.

## 구현에서 바꾸면 안 되는 핵심 구분

- 원작의 기술 라벨/숫자 ID가 곧 원작 대사나 자산을 가져오라는 뜻은 아니다. 자체 콘텐츠를 같은 구조·좌표·상태 계약에 넣는다.
- 화면에 먼저 보이는 값과 실제 상태 변경 순서를 바꾸지 않는다. 머신 선택 금액·위증 미결 비용·정산 카운트업·획득 표시가 대표 사례다.
- 준비/표현/완료·문맥 복귀를 한 프레임 즉시 처리로 합치지 않는다. 원작에 없는 안내/보장/자동 해금/편의 판정을 넣지 않는다.
- 실제 정상 흐름에서 쓰이지 않는 오류 후보·표의 미사용 열을 새 게임 규칙으로 만들지 않는다. 동시에 주요 정상 공백이 남았다면 그 기능을 추측으로 구현하지 않는다.

각 분야의 검토 상태는 progress.json과 진척률.md의 고정24×5기준을 따른다. 이 문서의 연결 표는 그 평가를 대신하는 단순 목록이나 별도의 완료 퍼센트가 아니다.

## 2026-10-26 완료 판정

고정24분야×5기준 모두2점으로240/240이다. 각 주요 정상 경로의 입력→조건→판정→실제 상태/화면·소리 소비→완료 대기→다른 모드/저장·호출자 복귀를 문서화했고, 남아 있던 조사 반응·패닉 화면·스크럼·차량·발굴·통상/최종무장·클라이맥스 표현을 통합했다. 자체 스토리와 세계관을 넣어 V3의 게임 방식과 틀을 구현하는 기준으로 사용한다. 구현할 때 핵심 규칙을 다시 추측하는 것을 전제로 하지 않는다.

최종 정상범위 교차 감사는 새 주요 기능 공백이나 근거에 반하는 핵심 연결을 발견하지 못했다. 개별 정적 helper, 근거 ID 색인, UTF-8/문서 차이 검사를 통과했다. 실제 원작 실행·모든 작성 변형·최종 픽셀/청취 실측 및 팬게임 구현 검증을 수행했다는 뜻은 아니다. 이 한계는 각 분야 원장에 보존하며 새로운 주된 동작이 발견되면 근거와 함께 명세를 갱신한다.
