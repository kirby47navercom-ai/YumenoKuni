# 16 — 장 끝·영상·종료의 연결

## 확인 범위

실효 US007의 `modSave CapterEndSave` 호출은8곳이다. 기술 도메인 chap0..chap7에 각각 한 곳이며, 이 숫자를 이야기의 장 수로 설명하지 않는다. 각 script SHA·offset·영상·장면 상태·후속 FIL/END는 외부 `native/chapter_boundary_findings.json`에 보존했다. 영상 내용이나 결말을 이 문서에 옮기지 않는다.

## 장 끝이라고 곧 프로세스를 종료하지 않는다

작성된 장면 상태 `end`, 장 끝 저장 요청, 다음 파일로의 이동, WRD의 `END`는 서로 다르다. `END` 처리기 `0x140464530`은 world+0xab68에1을 쓰고 현재 명령 실행을 양보한다. `0x140478c90`은 이 요청을 받아 정리 함수를 호출하고 진행 객체+0x6ad에6을 써서 바깥 실행 루프가 빠져나오게 한다. `0x140478780`은 소리·현재 문맥을 정리한 뒤 바깥 모드를 선택한다. 따라서 END를 애플리케이션 종료나 다음 장 시작으로 무조건 번역하지 않는다.

`CapterEndSave`는 mode parameter1이다. MOD의 저장 분기는 보통 다음 장의 선택 해금을 준비하고 저장 UI 객체 `0x14047c110`으로 이어진다. 하지만 현재 기술 chapter 값이7이면 world+0xb894=1을 쓰고 이 경로에서 저장 UI 생성 전에 반환한다. 이 flag는 바깥 정리 함수에서 소비해 바깥 상태0을 요청한 후 지운다. 최종 대본에도 `modSave`가 있다는 이유로 항상 같은 저장 창을 띄우거나 실제 파일 쓰기가 끝났다고 간주하지 않는다. 저장 파일 I/O와 완료 UI 자체는09를 따른다.

근거: END `ev_5ca5d4af6082438516e1a1a9e255258038317d4b6768256b5f2ebb5a7c24a46a`, world 진행 `ev_1e2569f99e90edbee790599afc84e8e6de22010a350f79d0c1963cc3cd1d09ea`, 바깥 정리 `ev_952d56d49ad85ace4c9eae4968182ea833fd9745c991c5934b10d0b693e3d209`, 저장 UI 생성 `ev_869c3b6d0c89043861747dd49531f72dd4ab5316da7fe35c8a90fc7cd7d80004`. 구조 offset의 원시 명령 대조는 외부 `native/chapter_end_field_references.json`이다.

## 영상 시작·대기·스킵·정리를 구분한다

MOV 처리기 `0x14046fc00`은 `MoviePlay`, `MoviePlayStop`, `MoviePlayEnd`를 구분하고 world+0xab38/+0xab3c에 하위 상태와 대기 종류를 설정한 뒤 양보한다. 갱신 `0x14047dad0`은 준비 완료 후 재생을 시작하고, 종료·스킵·해제 완료를 기다려 진행 잠금을 푼다. 일반 재생에는 논리 입력 bit0x400000을 읽는 스킵 분기가 있지만, 다른 대기 종류에서는 같은 분기를 타지 않는다. 대화 스킵 flag와 영상 스킵 입력도 같은 기능이라고 합치지 않는다. 아직 물리 키와 모든 영상의 허용 정책·실제 화면은 완료하지 않았다.

MOV가 기술 라벨을 받으면 `MovieGallery.dat`를 조회해 파일명을 얻고, 경로를 직접 받는 별도 분기도 있다. 예를 들어 movie_01/movie_16은 표에서 각각 movie/movie_01.mp4와 movie/movie_16.mp4로 연결된다. 이 표에 있다는 사실은 영상의 내용·크레딧 여부를 직접 확인했다는 뜻이 아니다. 지역화 파일 선택과 별도 오디오 큐 선택도 존재한다.

마지막 쪽의 작성된 전환도 단일 END가 아니다. 영상 두 번과 대기, 보상·해금·확인 입력, 장 끝 저장 요청 뒤 후속 기술 도메인으로 FIL이 이어진다. 후속 대본은 직접 경로 영상, 장면 end, 장 끝 요청, END를 사용한다. 전환별 offset과 파일 존재를 원장에 보존했다. 실제 영상·보상 화면을 끝까지 재생한 기록은 아니다.

근거: MOV `ev_3310b0d8098b3d20537870703fddb14efbd2b73e03286d1d86aab3f159e7ee52`, 대기 갱신 `ev_afc5449fcecb2fa8cacef6c14bf7ff2ba8e1790de772c96b99294be432819a42`, 상태 설정 `ev_47013b2f7e1c09def2fd30472f18678ee52be1ea7d8ad44e8cc75e3e798e4d14`.

## 유메노쿠니에서 바꿀 것

- `Game/Source/Flow.hpp`의 `eventsDone()/nextBeat()/enterBeat()`는 연출 완료·입력 확인·저장 UI 종료·후속 장면 진입·전체 문맥 종료를 따로 처리한다.
- `saveFlow()/loadFlow()`는 장 끝 요청이 언제 실제 저장을 수행하는지 정의한다. 원작의 명령 이름만 복사해 완료로 표시하지 않는다.
- `Game/tools/create-project.mjs`와 처형·장 끝 이벤트는 영상/슬라이드의 시작, 건너뛰기 허용 여부, 소리, 정리 후 다음 상태를 연결한다. 실행 화면 대조 전에는 원작 전환 시간을 임의로 확정하지 않는다.
- 이 문서는 분석 결과다. 원작 영상을 팬게임에 추가하거나 기존 구현을 변경하지 않았다.
