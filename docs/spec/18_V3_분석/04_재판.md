위 `Data` 분기는 `0x1404835c0`을 통해 대응 DAT를 읽는다. 패닉은 같은 로더를 하위 인덱스 0, 1, 2로 각각 호출하여 **세 개의 독립 데이터 열**을 준비한다. 스크럼은 공통 404바이트 로더 대신 `0x140484630`을 호출한다. 게임 시작·자료 적재·문장 실행·종료 상태를 재구현할 때 이 구분을 보존해야 한다.

`CHK`는 공개 도구의 주석에 적힌 “언령을 추가하는 명령”으로 단정할 수 없다. 실제 네이티브 `0x14045f600`은 `ChkEnd`, `ChkTimeOut`, `ChkHeartZero`, `ChkQuestion`과 진행 상태를 처리한다. 숫자 `CHK` 인자는 대응 논의 DAT의 레코드 +4바이트 키와 연결된다. 예를 들어 `nonstop_01_202.dat`의 18개 키와 `c01_202_001.wrd`의 숫자 `CHK` 18개 순서가 일치하고 끝에 `ChkEnd`가 온다. 모든 파일에 같은 순서가 적용된다고 일반화하지 않는다. 분기·추가 레코드·보조 열이 있다.

실제 언령 명령은 `KTD` 핸들러 `0x14046af30`에서도 따로 확인된다. `on`, `alloff`, `fl_in`, `fl_out`을 구분하고 언령 UI 루틴 `0x1403504a0` 및 등록 루틴을 호출한다. 획득 연출을 카드 하나의 정적 팝업으로 취급하기 전에 이 단계와 UI 애니메이션을 대조해야 한다.

선택은 인물 지목의 원형16순환과 다른 **4×4 격자**예요. `441340`은 열/행 float0..3을 따로 바꾸고 축 끝에서 순환하며, 별도 선형 이전/다음은 행 경계를 넘어 다음 칸으로 가요. `441e50/440d10`은 row×4+column을 반환해요. 이동은 SE367, 해당 커서 clip과3D 인물 표시 변경을 함께 요청해요. 논리 확인 `3c70f0`은 SE368·fl_ok 뒤 대기·발표로 넘겨요. 작성된 특정 장/플래그에는 일부 선택을 음성으로 거절하는 분기가 있어요. 영정 표시만 보고 보편적인 선택 금지를 만들면 안 돼요.

`4404c0`의14개 SFL 및 공통 사본 준비 뒤 `440d80`은 frame/start→인물·커서·버튼·이름·시계 진입 완료를 차례로 기다린 다음 활성4에서 입력을 받아요. 활성 갱신은 **입력441340 다음에 시간441f50** 순서예요. 마지막5×시간기준에서 시계 fl_rd_wait,0이면 SE332·timeup 진입, UI완료 뒤 실패사유를 남겨요. 일반 완료는 숫자0,시간실패는 ChkTimeOut이며 장별 종료/화면유지 분기는 관리자56/57에 별도로 있어요.

`441890`은16명 표시 상태, 선택 인물의 두 이름 텍스처·언어별 일부 숨김, 분/초/소수 자리별 숫자 교체를 소비해요. 이름과 시계가 선택 인덱스·카운터와 실제로 연결돼요. 결과 발표 sub2는 선택 인덱스를 결과 자식1로 넘기며 `442640`은 장별16개 표에 선택 인물 한 표를 더하는 경로와 특수 장 예외를 나눠요. `4420a0`은 SE369_d/특수465→배경/3D 인물 준비→fl_count→fl_happyo→이름/16표시 갱신→0x79카운터 유지→퇴장을 기다려요. 이 결과 단계에 새 인물 선택 입력을 추가하지 않아요.

일반Choice/세 지목의 표현은 위 절과02, 정산은18의 합계→벌점·배수→등급·목록→8행 상세/확인→fade·해제→저장/WRD 복귀를 함께 따르면 주요 정상 화면 연결을 재구성할 수 있어요. 모든 투표 영상 변형이나 실제 픽셀/시간 실측까지 확인한 결과는 아니에요. 외부 `trial_vote_contract.py/findings.json/sfl_contract.json`은 PE SHA·19함수·기존14SFL의 라벨/배치 메타데이터를 검사해요.
