# 17 — 탈출 액션의 조작·추종·접촉·결과 복귀

## 확인 범위

설치본 자료와 native 정적 분석이다. 원작 실행으로 이 모드를 플레이하지 않았다. 원본 트랙·그림·대사·상세 디컴파일은 저장소 밖에 유지한다. 트랙15개는 head/back/center/front/eline 각3개의 자료이며, 서로 다른15개 플레이 스테이지라는 뜻이 아니다. native는 stage000..005의6개 모드 라벨을 구분한다. 트랙 선택 인수와 모드 번호는 별도다.

실효 US007의2,716개 스크립트에서 `modEscape`15호출을 찾았다. non-test7호출, test8호출이며 non-test는 서로 다른5개 stage 라벨을 사용한다. 모든15호출에 종료 결과10000/10001의 두 분기와30개 실제 목적 라벨이 있다. 이 전수 검사는 해당 호출 뒤의 CHK 블록을 검사한 것이며 모든 조건에서의 도달성·모든 대사 콜백의 실행 증명은 아니다. 외부 `native/escape_script_calls007.json`, 재현 `analyze_escape_flow.py`에 파일SHA·명령offset·분기/목적 구간을 보존한다.

## 진입부터 종료까지

MOD9 요청은 본편 controller의 탈출 상태로 들어가 `0x140147f50`을 호출한다. 이 함수는 맵 자료, 배경, 장애물, 캐릭터, HUD/컷인 객체를 따로 만들고 모두 준비될 때까지 기다린다. 시작 컷인 완료 후 캐릭터 입력을 활성화한다. 일반 플레이 상태에서는 도움말 요청을 받고, 모달 대기 중에는 다음 scheduler 호출로 돌아가 게임 구성요소의 갱신을 건너뛴다. 전체 모드가 타이틀과 같은 입력 루프 하나로 움직이는 것은 아니다.

주요 구성요소는 맵 `148890/148e00`, 배경 `14e9c0/14eff0`, 장애물 `14aa30/14b410`과 `14d0a0/14dbd0`, 캐릭터 `14fd10/150410`, HUD/컷인 `152b70/152da0`이다. main은 이 객체들 사이의 포인터를 연결한다. 각 객체의 기능 이름은 이 연결과 실제 소비를 따른 분석 명칭이다.

## 선두 조작과 움직임

`150410`은 살아 있는 목록의0번에 실제 입력을 넣는다. 좌/우 held 입력은 `3c15e0/3c1630`, 위/아래는 `3c1680/3c1590`이다. 기본 키보드 좌우는 A·왼쪽 화살표 / D·오른쪽 화살표와 연결된다. 패드는 D-pad와 스틱 방향 비트의 조합을 받는다.

점프는 held `3c16d0`와 새 누름 `3c1770`을 함께 사용하고, 접지(+0x9c=1)·비점프(+0x88=0)를 확인해 시작한다. held는 기본 W·위쪽 화살표와, 전역 결정 배치에 따라 선택되는0x20/0x40을 받는다. 따라서 W/↑ 외의 face 버튼·기본 키는 배치에 따라 달라진다. 일반 배치가0이 아니면0x20=Escape/R/X,0이면0x40=Z 경로다. 이 기능을 본편의 일반 조사/확정 키와 동일시하지 않는다.

점프의 공중 수직 계산은 이전 값·현재 값·경과 카운터를 보존한다. 초기 구간10회 미만에서는 held 유지에 따라 계수를0.25배 하는 분기가 있어, 누름과 놓음이 같은 고정 포물선 하나로 축약되지 않는다. 좌우 가속도 방향 전환과 같은 방향 유지가 다르다. 소비 코드에는0.3/0.8 증가·감소와 최대 크기6.6이 있고, 무입력에서는 기존 값/1.1로 감쇠시키다가 크기0.1 이내에서0으로 만든다. 이는 모드 내부의 호출당 수치이며 meter/초가 아니다.

별도 행동 `3c1430`은 오른쪽 마우스 held 또는 위의 점프 face 버튼과 반대인0x40/0x20을 받는다. 캐릭터 쪽은20카운터 간격을 두고 행동을 시작하며 모드0/5에서 추가 궤적·접촉 호출을 수행한다. 궤적은 분석했지만 이를 모든 모드의 같은 명칭·같은 장애물 파괴 능력으로 일반화하지 않는다. `3c14f0`의 새 누름(가운데 마우스 또는0x10/기본 Enter)도 별도 반응에 쓰인다.

## 뒤따르는 캐릭터는 현재 위치 복사와 다르다

초기화 `14ff60`은1,500개×84바이트의 이력 영역과 최대17개 캐릭터 슬롯을 준비한다. 선두의 이력 번호는3000으로 시작하고 뒤의 캐릭터들은 순서에 따라25×순서+12의 차이를 둔다. 사용 인덱스는 이력 번호%1500이다. 뒤따르는 캐릭터들은 이력의 위치·입력·이동/점프 상태를 읽고, 자신의 장애물·접지·구간 제한도 확인한다. 따라서 같은 프레임의 선두 위치를 일정 거리만큼 복사하는 추종과 다르다.

## 유메노쿠니에 적용할 판단과 남은 일

이 모드의 핵심은 선두 조작뿐 아니라 생존 집단·뒤따르기·선두 교체·스크롤·장애물별 반응의 연결이다. 자체 스토리·세계관에 맞는 캐릭터·맵을 사용하되 이 규칙 전체와 다른 시스템의 연결을 분석하고 재현 대상으로 삼는다. 본편 탐색과 다른2D 이동/접촉·held/edge 점프·이력 기반 추종을 하나의 일반 이동 함수로 축약하지 않는다. 입력 중단·도움말·시작/종료 컷인·결과 반환도 플레이 루프에 포함한다.

## 모드별 생존 명단·공격·장애물·정상 표현의 후속 연결
