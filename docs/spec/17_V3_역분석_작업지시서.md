# 제작 사양서 17 — 단간론파 V3 전체 역분석 작업지시서 (코덱스용)

**최신 작업 목표:** 유메노쿠니의 스토리와 세계관은 유지한다. 게임 방식·게임 틀·맵과 이동·조작·일상·자유행동·수사·재판·미니게임·보너스 모드·메뉴·저장·UI·연출 등 게임 시스템 전체는 V3를 기준으로 전면 재구성한다. 기존 구현에 있다는 이유로 보존하거나, 없다는 이유로 분석·재현 범위에서 제외하지 않는다. 먼저 V3 전체의 규칙과 연결을 분석하고 미확정 부분을 구분한 뒤 그 근거로 게임을 고친다. 현재는 분석 단계이며 게임 코드를 변경하지 않는다. 원작 파일의 게임 내 사용·배포 제한은 유지한다.

> 주인님 지시 : 「게임 자체 모든 것을 역분석해서 단간론파처럼」. 지금까지는 위키 스크린샷·기억으로 짐작해 만들어 재판·탐색·일상이 V3 와 어긋났다.
> 이 작업은 **짐작을 실측으로 바꾸는 것**이다. 결과 문서대로 유메노쿠니를 화면 하나하나 다시 만든다.
> 먼저 `HANDOFF.md` 를 처음부터 끝까지 읽는다(엔진 제약·빌드·검증 방법).

## 2. 무엇을 봐야 하나 (자세한 체크리스트 — 게임 전체)

> **주의 : 아래 항목 안에 적힌 원작 동작(「3인칭」「조준점」「빌보드」「휩」 등)은 Claude 의 기억·추정이다. 확인된 사실이 아니다.** 그대로 받아들이지 말고, 데이터와 실제 화면으로 맞는지 틀렸는지 판정해 적는다. 추정과 다르면 원작 쪽이 정답이다. 목록에 없는 동작·화면을 발견하면 추가한다.

### 2-0. 공통 방법
* 항목마다 **(a) V3 실제 동작 (b) 근거 : 파일 경로·명령 이름·인자·수치 (c) 유메노쿠니 지금 상태(파일·함수) (d) 바꿀 것** 을 쓴다. (b) 가 없는 항목은 「추정」이라고 적는다.
* **데이터만 보지 말고 실제 화면과 맞춘다.** 장면마다 다음을 한 묶음으로 둔다 : ① 대본(wrd) 명령 목록 ② 그 장면 실제 플레이 영상의 시각(주인님 녹화본 또는 공개 플레이 영상의 몇 분 몇 초) ③ 명령 ↔ 화면에서 일어난 일 대응표. 이 대응으로 명령 뜻을 확정한다.
* 수치는 원작 해상도 1920×1080 기준으로 재고, 우리 1280×720 값(×2/3)을 같이 적는다. 시간은 프레임(60fps)과 초를 같이.
* 같은 종류 장면은 **장마다 하나 이상**(프롤로그·1~6장) 표본을 본다. 장마다 다른 것(곡·연출)과 늘 같은 것(UI·규칙)을 나눠 적는다.
* 파일 이름 규칙(장·장면 번호 → 파일)은 가장 먼저 **파일 목록 전체 표**(`docs/spec/18_V3_분석/files.md` : 아카이브 → 안의 파일 → 무엇인지)로 먼저 만든다. 이후 모든 근거는 이 표의 이름으로 적는다.

### 2-1. 대본(wrd) 명령 — 모든 연출의 열쇠 (가장 먼저)
* 명령(opcode) **전부**의 이름·인자 형식·뜻. 공개 소스의 표에서 시작하고, 뜻이 비어 있는 명령은 실제 화면 대조로 채운다.
* 명령을 종류로 묶어 정리 : 대사 표시 / 화자·입상 표시·교체·퇴장 / 입상 위치·크기·움직임 / 카메라(3D 카메라 이동·회전·줌·흔들림) / 배경·맵 전환 / BGM 시작·정지·페이드 / 효과음 / 음성 / 화면 효과(암전·플래시·색·컷인·글자 연출) / 대기·시간 / 분기·플래그·선택지 / 미니게임 호출 / 저장 / 장·장면 이동.
* 각 명령이 **대본 전체에서 몇 번 쓰이는지**(빈도표). 자주 쓰는 연출이 V3 다움의 핵심이다.
* 화자 표시 방식 : 이름표·입상·음성이 어떤 명령 조합으로 나오는지, 독백(주인공 속마음)과 대사의 구분.
* 입상 번호 규칙(인물 번호 × 표정 번호) → 표정 종류 목록과 **대사 몇 줄마다 표정이 바뀌는지** 통계(우리 `tools/pose_design.py` 와 비교).

### 2-2. 전체 흐름·진행 구조
* 게임 시작 → 타이틀 → 프롤로그 → 1장 … 6장 → 에필로그 : 장면(대본 파일) 순서 전체를 표로.
* 한 장 안의 단계 : 일상(몇 일, 하루에 무엇) → 동기 발표 → 사건 → 시체 발견 → 수사 → 수사 종료 → 엘리베이터 → 재판 → 처형 → 장 끝. 각 단계 전환을 일으키는 **명령·플래그·조건**.
* 하루의 구조 : 아침 방송 → 자유 시간(몇 번) → 이벤트 → 밤 방송 → 취침. 「지금 할 일」(목적지) 표시 방식.
* 구역 개방(새 장마다 열리는 곳)이 어떤 데이터로 정해지는지.
* 저장 시점·자동 저장, 장 선택.

### 2-3. 탐색 — 가장 크게 어긋난 곳 (가장 자세히)
**바깥(캠퍼스) 이동** — 3인칭인지, 시점·조작이 어떤지부터 확인
* 맵 데이터 파일(3D 메시·충돌·문 위치·구역 경계·인물 자리)의 구조와 좌표 단위.
* 주인공 : 모델인지 입상인지, 크기, 걷기·달리기 속도(m/s), 회전 속도, 애니메이션.
* 카메라 : 주인공 뒤 거리·높이·숙임 각, 시야각(FOV), 따라오는 지연(부드러움 값), 벽에 닿을 때, 오른쪽 스틱/마우스 회전 범위.
* 문·출입구 : 판정 범위, 「들어간다」 표시, 들어갈 때 연출(암전 시간·효과음), 잠긴 문.
* 미니맵 : 위치·크기·회전 여부·표시하는 것(목적지·인물·문).
* 목적지 표시·「지금 할 일」, 이동 제한(못 가는 곳 안내).

**방 안** — 1인칭인지, 걸어 다니는지부터 확인
* 카메라 높이, 시야각, 이동 가능한가(어디까지)·속도, 시점 회전 범위(좌우·위아래 제한), 회전 감도.
* 조준점(커서) : 모양·크기, 조사 대상 위에 올렸을 때 변화(색·「!」·「?」·이름 표시), 판정 방식(화면 거리? 3D 광선?).
* 조사 대상 데이터 : 방마다 대상 목록, 3D 위치, 크기(판정 상자), 이름, 실행할 대본 번호, 조사 후 표시(회색·체크).
* 물건 치기(코인) : 어떤 물건이 반응하나, 코인 개수, 연출.
* 방 들어갈 때·나갈 때 연출, 방 안 인물에게 말 걸기 판정.

**인물 배치**
* 인물이 2D 입상인지 3D 모델인지, 3D 안에 어떻게 그려지나 : 빌보드(항상 카메라를 봄)인지, 고정 방향인지, 크기(키 비례인지), 발 위치·그림자.
* 방·캠퍼스마다 인물 자리 데이터(장·날짜·시간대별로 바뀌는 표).
* 말 걸기 범위·표시.

**패드(모노패드) 지도**
* 3D 조감 지도인지 2D 그림인지, 층·구역 전환, 현재 위치·인물 얼굴·목적지 표시, 빠른 이동 가능 여부.

**수사 중 탐색 차이**
* 수사 때만 켜지는 조사 대상·대사, 「수사 개시」 표시, 언령을 얻는 대상과 그렇지 않은 대상의 표시 차이, 필수 언령을 다 모으면 일어나는 일.
