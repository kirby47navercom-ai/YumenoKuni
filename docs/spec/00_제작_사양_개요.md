# 유메노쿠니 제작 사양서 00 — 개요 · 아키텍처 · 데이터 파이프라인

> 목적 : `docs/design/`의 **각본(대사 3,164줄)** 과 **캐릭터 설정**만으로 바로 구현에 들어갈 수 있게, 엔진·구조·데이터·연출·UI·미니게임·에셋을 확정한다.
> 레퍼런스 : 단간론파 시리즈(탐색 + 비주얼 노벨 + 재판 액션). **원본 게임은 지금 단계에서 필요 없다** — 수치(속도·판정)는 이 문서에서 확정했고, 플레이 테스트 때 체감 비교용으로만 쓴다. 필요해지면 그때 요청한다.
> 문서 구성 : `00 개요` / `01 스크립트·연출 명령` / `02 UI 화면` / `03 탐색·수사` / `04 재판 미니게임` / `05 연출 가이드` / `06 에셋 목록` / `07 데이터 스키마` / `08 구현 로드맵` / `09 챕터 플로우` / `10 장면 인덱스(자동 생성)`.

---

## 1. 제작 목표

| 항목 | 값 |
|---|---|
| 플랫폼 | **Windows PC** (1차) / 이후 Steam Deck·Mac 가능 |
| 해상도 | 기준 **1280 × 720 (16:9)**, 1920×1080까지 스케일. UI는 기준 좌표계 사용 |
| 프레임 | 60fps 고정 (재판 액션 판정이 프레임에 의존) |
| 입력 | 키보드+마우스 / 게임패드(XInput). 모든 화면은 둘 다 조작 가능 |
| 언어 | **한국어(기본)**. 텍스트는 키로 분리해 다국어 확장 가능 |
| 플레이 타임 | 약 **45시간**(프롤로그 2h + 1~5장 각 7h + 6장 5.7h) |
| 연령 | 처형 연출은 **잔혹 묘사 금지**(빛·소리·실루엣) — 연출 가이드 05 참조 |

## 2. 엔진 · 기술 선택

### 2-1. 권장 : **Godot 4.3 (GDScript)**
| 이유 | 설명 |
|---|---|
| 2D UI 중심 | 대화·UI·재판 미니게임이 대부분 2D. Godot의 Control 노드·애니메이션 트리가 적합 |
| 탐색 구현 | 1인칭 탐색은 **파노라마 노드 방식**(§4)이라 3D 풀 구현이 불필요 |
| 데이터 구동 | JSON 로드가 단순. 이 저장소의 `data/*.json`을 그대로 사용 |
| 비용 | 무료·오픈소스. 소규모 팀(학생 개발)에 적합 |
| 대안 | Unity 2022 LTS (C#)도 가능. 이 문서는 엔진 중립이며, 클래스명만 바꾸면 된다 |

## 3. 저장소 구조

```
YumenoKuni/
├─ docs/design/        각본·캐릭터·시스템 기획 (사람이 읽는 원본)
├─ docs/spec/          제작 사양서 (이 문서군)
├─ data/               tools/build_data.py 가 생성하는 게임 데이터
│  ├─ scenes/*.json      장면별 이벤트 (3,164 events)
│  ├─ evidence.json      증거·증언·마법·노트 카드 (123장)
│  ├─ characters.json    17명 인적사항
│  ├─ emotion_map.json   표정/연출 태그 → 표정 ID
│  └─ scene_index.json   장면 292개 (위치·출연자·분량)
├─ art/standing/       기준 입상 17장
├─ tools/              generate_tpose_nai.py / build_data.py
└─ game/               (엔진 프로젝트 — 앞으로 생성)
   ├─ scripts/ scenes/ ui/ assets/ (08 로드맵 참조)
```

### 3-1. 데이터 빌드
```bash
python tools/build_data.py     # docs/design → data/
```
* 각본(md)을 고치면 이 명령으로 JSON을 다시 만든다. **게임은 md가 아니라 JSON만 읽는다.**
* 변환 규칙 : 코드블록 안의 `[화자] "대사" {표정}` → `say`, `(지문)` → `stage`, `[UI] …` → `ui`, `▶…` → `choice`, `── … ──` → `break`. 그 외 줄은 `note`(제작 메모, 게임에선 숨김).
* **`[복선]` 표기는 `note`로 보존되고, 빌드 옵션으로 제거할 수 있다**(`--strip-notes`는 구현 항목, 08 로드맵 M1).

## 4. 탐색 방식 결정 : "파노라마 노드"

| 항목 | 결정 |
|---|---|
| 방식 | 장소마다 **정지 노드**를 두고, 각 노드는 **360° 파노라마(또는 광각 일러스트)** 를 렌더. 시점 회전 = 마우스 드래그(패드 우스틱), 이동 = 노드 클릭 |
| 이유 | 제작비·일관성·연출 통제. 1인칭 3D 자유 이동보다 20% 비용, 단간론파식 "방 단위 탐색" 체감은 동일 |
| 제작 | 배경은 **Blender로 모델링 후 파노라마 렌더**(저장소 환경에 Blender MCP 있음) 또는 2D 일러스트 파노라마 |
| 핫스팟 | 파노라마 위에 클릭 영역(원/다각형)을 둔다. 확대 조사 = 확대 이미지 + 관찰점 최대 3개 |
| 전환 | 노드 이동 0.5초 페이드(또는 슬라이드 + 블러) |
* 상세는 03 문서.

## 5. 게임 상태머신

```
[Boot] → [Title] ─┬─ New Game ─▶ [ChapterFlow(P)]
                  ├─ Continue
                  └─ Options / Extras

ChapterFlow(n) = beats[] (09 챕터 플로우):
   story → freetime → story → freetime → story → freetime → motive → night_story
   → incident → discovery → investigation → trial → execution → epilogue → next chapter

Beat 종류:
  story        ScriptRunner가 scene id 목록 재생
  freetime     FreeTime 세션 (2슬롯)
  explore      Exploration(자유 탐색, 과제/타이머 포함)
  investigation Investigation(타이머 + 현장 목록)
  trial        Trial 파이프라인 (04)
  execution    Cinematic(처형)
  save         오토세이브 포인트
```

## 6. 세이브 데이터

### 6-1. 파일
* 슬롯 20개 + 오토세이브 3개(롤링). JSON(`save_{slot}.json`) + 썸네일(PNG 320×180).

## 7. 품질 기준

| 항목 | 기준 |
|---|---|
| 텍스트 | 대사창 한 화면 최대 3줄(줄당 36자). 넘치면 자동 분할 |
| 입력 지연 | 클릭→반응 ≤ 100ms (재판 액션은 ≤ 50ms) |
| 로딩 | 장면 전환 ≤ 2초 (스트리밍 프리로드) |
| 접근성 | 색약 모드(노란/파란 마크에 패턴), 텍스트 크기 3단계, 자막 상시, 번쩍임 감소 옵션 |
| 세이브 | 장면 전환·프리타임 종료·재판 단계 종료마다 오토세이브 |
| 안전 | 번쩍임 효과 초당 3회 이하(광과민성 가이드) |

## 8. 용어

| 용어 | 의미 |
|---|---|
| 비트(beat) | 챕터 흐름의 한 구간 (스토리·프리타임·재판…) |
| 장면(scene) | 스크립트 한 덩어리 (예 : `1-S2`) |
| 이벤트(event) | 장면 안의 한 줄 (대사·지문·UI·선택) |
| 증거 탄환 | 재판에서 쏘는 증거 카드(노랑) |
| 노트 승격 | 증거를 노트 증거(변조 불가)로 올리는 행위 |
| BP / Lv | 인연 포인트 / 인연 레벨 |
| SP / MP | 스킬 장착 코스트 / 재판 중 사용 코스트 |
