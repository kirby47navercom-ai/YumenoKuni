# V5 문체 교정 — 2026-11-10

프롤로그부터 6장, 1장 별도 재판 원고, 자유시간의 9개 본문에서 **632발화**를 고쳤다. 일반 대사 577개와 번호가 붙은 재판 발언 55개다. 게임 데이터에서는 같은 대사의 후속 큐·재판 사본을 포함하여 687개 텍스트 필드가 바뀐다. 원고의 발화와 게임 데이터의 사본을 합산하지 않는다.

## 표현을 고친 기준

- 모든 인물이 허락·기록·관찰의 한계를 같은 어조로 설명하던 부분을 줄였다. 수사의 근거 구분이 필요한 질문은 남겼다.
- 사츠키는 짧은 질문과 거절, 아이는 조심스러운 존댓말, 레이는 정중한 거리, 쇼는 관찰한 상태와 판단의 한계가 드러나게 고쳤다. 서로의 말투로 바꾸지 않았다.
- 켄과 리쿠는 각각 무대에서 상대를 떠보는 말과 사적인 장난을 구분했다. 하루카와 유우는 관계에서 무엇이 섭섭하거나 두려운지 직접 묻게 했다.
- 나나의 돌봄과 거절을 장황한 해명 대신 구체적인 부탁으로 바꿨다. 아카리가 공개 자리에서 쓰는 존댓말과 사적인 대면의 반말은 구분해서 유지했다.
- 카에데가 평소의 담백한 반말과 달리 이유 없이 존댓말을 쓰던 식사·문서 대면을 고쳤다. 낯선 사람에게 외치는 요청과 식사 인사까지 반말로 일괄 변환하지 않았다.
- 미오의 독백이 장면의 의미를 설명하던 곳은 실제로 보고 신경 쓰는 대상으로 옮겼다. 재판에서의 관찰·추론·거짓말은 구별했다.
- 래피의 초반 안내와 후반 응답은 같은 장난조로 통일하지 않았다. 소라와 타이가의 도움·보호 욕구가 단순한 절차 설명으로 들리던 대사를 고쳤다.

각 수정문을 원문과 다시 대조했다. 가능성을 확정으로 바꾸거나, 말하는 사람과 듣는 사람을 바꾸거나, 완료된 행동을 앞으로 할 행동으로 바꾸는 교정은 바로잡았다. 정확한 전후 문장은 **스포일러가 있는** `data/revised_voice_polish.json`에 남겼다. 이는 수정한 632발화의 기록이며 V5의 모든 발화를 다시 썼다는 뜻은 아니다.

## 연결과 저장 보존

`tools/revised_voice_polish.py`는 교정된 원고의 발화 주소를 교정 전 주소에 대응시킨다. 원고 자체에 수정문을 쓰며, 실행 시 옛 문장을 몰래 치환하는 방식은 아니다. 화자·장면·줄 수·강조 단어·숫자를 보존했다.

수정 전후 컴파일 결과를 전체 대조한 결과, **21,603노드의 ID·분기·선택지·획득 조건과 277과제의 정답·증거·배역을 포함한 비텍스트 필드가 전부 동일**했다. 변한 필드는 발화 텍스트뿐이다. 기존 저장을 지우거나 V6 저장 영역을 만들지 않았다.

## 완료한 데이터·출력 검사

- 원고 632개 수정문이 컴파일 결과에 모두 존재한다. 발행한 전체 노드·과제도 컴파일 결과와 일치한다.
- 선택 순서를 바꾼 두 데이터 경로가 프롤로그부터 6장 각 종료와 서로 다른 최종 선택까지 도달한다. 과제 성공을 가정한 데이터 검사이며 실제 전편 플레이 시간 측정은 아니다.
- 현재 게임의 C++ 페이지 분할기로 수정 발화 632개를 일반창·재판창 두 규격에 넣었다. 1,274페이지의 원문 바이트·줄 수·폭 검사가 통과했고 문장 중간의 페이지 경계는 없었다. 재판 번호 발언도 이 검사는 보수적으로 두 창에서 시험했다.
- 실제 일반 본문 `Main.Body`가 쓰는 Pretendard Medium과 재판·로그의 Pretendard Regular에서 수정문에 쓰인 문자 571종의 누락이 없다. 장식 글꼴을 본문 글꼴로 잘못 검사한 결과를 본문 누락으로 보고하지 않는다.
- 새 주소 대응 632개와 다른 장면에 같은 문장이 나왔을 때 대응이 번지지 않는 632개 검사를 통과했다.

검사 스냅샷과 전후 비교, 현재 생성 결과 대조는 `Game/Saved/v5-prose-polish-20261109/`에 있다. 원작 실행·엔진 수정·정상 저장 변경 없이 작업했다.

## 실제 출력 검사에서 발견한 재판창 오류

일반 대사 두 지점의 표시·패드 복귀·다음 발화는 통과했지만, 재판창에서는 실행기가 종료됐다. 오류의 겉 메시지는 자원 해제 실패였다. 배포 도구를 바꾸지 않고 검사 프로세스에서만 내부 오류를 출력해, 실제 원인이 **없는 `body._left.png` 참조**임을 확인했다.

게임의 `Game/Source/DialogueWindowV4.hpp`에서 파일명 네 글자를 자르고 PNG를 붙이던 함수가 원인이었다. 최적화된 원본 경로는 `body.webp`이고 실제 조각은 `body_left.webp`다. 확장자의 마지막 점에서 이름과 확장자를 나누어 조각 이름을 만드는 함수로 수정했다. 6개 장의 프레임과 유·무명 본문을 포함한 실제 27조각 경로, PNG·WebP·점 있는 폴더·역슬래시·확장자 없는 경로의 총 33개 C++ 검사를 통과했다.

처음 패드 검사가 실패한 것은 두 Tab 입력 사이가 짧아 닫힘이 무시된 검사 준비 문제였다. 패드 root의 실제 표시·해제를 기다리도록 검사기를 고쳤다. 이 문제와 위의 실제 자산 참조 결함을 섞지 않는다. 실패 보고서도 보존했다.

`verify-flow.mjs`는 레거시 WebView용으로 네이티브 실행을 거절했다. 이 거절을 플레이 검증 통과로 기록하지 않았다.
